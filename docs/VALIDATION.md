## 十项核心测试

| 项目 | 检查结果 |
| --- | --- |
| 汇报和建议不执行 | 消息与建议生成后任务对象不变，没有写入回执 |
| 两种 Ontology | 同一 API 合约运行 TransferLeg/Vehicle 与 Session/Room，映射各自领域行动 |
| 幂等 | 重发同一请求返回同一回执，幂等键换内容被拒绝 |
| 版本冲突 | 对象变化后，原建议不能覆盖新状态，也不留下部分写入 |
| 角色/任务范围 | 工作人员不能重分配资源，也不能操作或汇报他人任务 |
| 跨活动引用 | 外活动对象、消息与建议不能用于本活动写入 |
| 资源条件 | 已占用、容量不足、原有资源不能作为错误的备用分配 |
| 建议与提交匹配 | 改动建议参数被拒绝；缺少关联任务不猜测对象 |
| 持久化 | 新应用实例读取同一数据库后，消息、版本与回执保留 |
| 并发预留 | 两个任务同时申请同一备用车，只有一个成功，另一个 409 |

接单与换资源均保持服务进度不变；这也是测试断言的一部分。
