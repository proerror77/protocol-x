# QRF 接机演练

1. 在独立的试点数据库运行现有 Ops 服务。用两个独立身份登录，一位中台调度员和一位 Android 一线人员。
2. 中台通过现有派单入口给一线发一张接机任务，地点填「机场 3 号门」。Android 在任务详情底部依次点「确认接单」「确认出发」「确认到场」。每一步的状态和回执都能在工作区读回。
3. 在同一张任务卡点「异常回报」，说「我到 3 号门了，还没找到客人，请调度协助」。草稿显示识别原句和可编辑的回报正文。核对后点「确认发送」。
4. 用调度账号打开 Web 指挥台的「团队汇报」，找到与该接机任务关联的异常，点「确认收到异常」。Android 重新同步后在任务卡和「本任务回执」显示中台确认。
5. 检查「交接」仍是当前待确认节点，并核对中台回执引用的是同一条异常。

## 服务配置

用 `requirements-transcription.txt` 的现有转写环境运行 Ops，并设置 `OPS_QRF_WHISPER_PATH` 为本地 faster-whisper 模型目录。录音最长 15 秒，后端转写后释放音频。本版支持直接输入原句。输入或录音均需通过草稿预览才能提交。

设置 `OPS_QRF_AGENT_MODEL` 为受授权的模型，使用现有的 Anthropic Messages 兼容入口。`ANTHROPIC_BASE_URL` 填服务根地址，凭据由后端从 `ANTHROPIC_AUTH_TOKEN` 或 `ANTHROPIC_API_KEY` 读取。模型仅接收转写的原句或键入的内容。任务引用和发件人由服务端绑定。未设置模型时，接单和进度操作仍可用，异常页会提示草稿服务不可用。

Android debug APK 可连接本地演练实例。模拟器使用 `http://10.0.2.2:<端口>`。正式使用的地址和凭据由部署环境配置。

## 本次验证

独立演练数据库中，Android 15 模拟器完成接单、出发、到场，由模型生成异常草稿，经本人确认后提交。Web 指挥台点击「确认收到异常」，Android 读回对应回执，交接仍待确认。模型链路使用已有兼容入口，另用合成中文录音验证了本地 Whisper 转写到草稿和回执的流程。实体手机麦克风和生产环境待实测。

## v0.14 频道回报

在「对讲」里选择有权限的工作群组并加入频道。按住 PTT，带上会合点或航班号说出现场异常，松开后回到收听。频道保留原音和转写。已识别的异常在同一句下显示登记及调度确认状态。

转写由香港部署中的 Whisper 工作进程处理。系统自动登记明确的车辆故障、会合异常、到达延误和协助请求。系统依据发言人的活动任务及发言里的标识关联任务。有多项可能关联时，先登记频道异常并提示补报航班号或会合点。车辆故障可生成通过容量和预留检查的换车建议，由调度员确认。

验收时使用独立的演练频道和演练任务。核对发言原音、转写、异常消息里的语音轨道标识、匹配任务和调度确认回执。频道发言有歧义或语音只保留部分内容时，保留原音供核对。

## v0.15 频道内调度和原音回听

频道动态与 PTT 位于同一页面。原音就绪后即可回听，转写在独立任务中更新。最近三条短语音可预取到设备加密缓存。缓存按账号、服务器、活动、频道和轨道区分，最多保留 12 MiB，24 小时过期。退出对应登录时清理缓存。首次未命中时从 PCM 流读取第一段就开始播放。

调度建议卡列出当前任务、分派状态、航班、车辆、会合点和接收人。调度员可修改并确认发送指示。确认换车沿用任务版本、车辆可用性和预留检查，同一事务写入换车和指示。一线在该频道查看指示并确认收到，确认留下独立回执。

香港工作频道使用 CPU 上的 SenseVoice int8，经 `OPS_PTT_SENSEVOICE_MODEL_DIR` 指定本地模型目录。目录需包含 `model.int8.onnx` 和 `tokens.txt`，工作进程使用 sherpa-onnx。原有 Whisper 作为备用。接机演练语音用 PostgreSQL 中的同一轨道编号将原音、转写、异常、指派和通知关联。

## v0.16 本机字幕、缓存和百炼复核

「频道工具 → 下载离线字幕包」安装一次约 240 MB 的 SenseVoice int8 资源。应用通过 LiveKit 的本地和远端音轨取得 PCM。在有模型的手机上，本机字幕用同一个发言轨道编号作为草稿；服务器复核完成后更新同一条记录。锁屏收听不运行本机字幕模型，音轨仍可缓存。

发出和收到的有效 PCM 都可以直接生成加密本机回放缓存。历史录音加入频道后预取最近八条，单条最长 90 秒。缓存总量至多 24 MiB，24 小时过期。点击未命中的录音会暂停预取，优先让这条原音边收边播。退出个人账号时清理该账号的原音缓存。

香港服务器以当前任务航班和会合点核对服务器转写。明确发言航班与任务无匹配时保留待核对异常。调度员核对 Agent 建议后才能修改任务或发送指示。

香港工作进程可设置 `DASHSCOPE_API_KEY`、`OPS_PTT_DASHSCOPE_WORKSPACE`、`OPS_PTT_DASHSCOPE_REGION` 和 `OPS_PTT_DASHSCOPE_CHANNELS`。最后一项由明确的工作群组 ID 组成，使用逗号分隔。新加坡百炼调用 `qwen3-asr-flash`，范围为该名单内的已授权频道。百炼失败时使用香港本机模型。密钥由 systemd 读取服务器的私有环境文件。

接收端加入频道后由 mediaPlayback 前台服务继续收听。可在频道工具选择扬声器、有线设备或支持通话的蓝牙设备，应用记住所选路由。使用蓝牙通话设备时可在同一菜单授权。纯媒体型蓝牙音箱应单独验收。

## v0.16.2 字幕路由

对讲原音沿用同一个轨道。APP 在可用网络下优先等待服务器复核。当前等待窗口是 2.5 秒，从本机原音准备好开始计时。网络不可用、频道归档读取失败、服务器未识别出文字或等待超时后，APP 即可用已安装的模型回退生成本机字幕。服务器复核稍后到达时更新同一条字幕，Agent 继续使用服务器结果。实时对讲需要已连接的频道。
