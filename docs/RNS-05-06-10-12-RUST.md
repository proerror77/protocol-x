## 1. Architecture Summary

### RNS-05: Private-Network IFAC Isolation, Dynamic Rotation, Revocation & Actor Binding (`src/ifac.rs`, `src/node.rs`)
- **Zero-Public Default & Boundary Masking:** When `NodeConfig.ifac` is configured (or `NodeConfig.require_private_ifac == true`), interfaces attach via `add_interface_with_ifac_name` / `supervise_with_ifac_name` using Reticulum-compatible IFAC (`IfacContext::derive`, default `IfacSize::WIDE` = 16 bytes matching Python `RNS.Transport` `DEFAULT_IFAC_SIZE = 16`). Non-IFAC, wrong-IFAC, and unauthenticated frames are masked/unmasked and rejected at the interface wire boundary. Startup with `require_private_ifac = true` and `ifac = None` returns `ProtocolxRnsError::InvalidMaterial`.
- **Event / Channel Key Derivation (`derive_event_ifac_config`):** Deterministic HKDF-SHA256 derivation from `event_id`, optional `channel_id`, `shared_secret`, and `key_epoch`, producing `IfacConfig { network_name, passphrase, ifac_size_bytes: 16, rotation_epoch }`.
- **Dynamic Credential Rotation (`RnsNode::rotate_ifac_credentials`):** Suppresses false `on_interface_detached` callbacks via `BridgeDetachHandle::suppress()`, tears down active supervisors/TCP servers (`AttachedSupervisor::teardown()`), clears active custom lanes cleanly, and re-attaches configured TCP and custom bridge interfaces with the new `IfacContext` and network name.
- **Peer Revocation & Blackholing (`revoke_peer`, `unrevoke_peer`, `revoked_peers`):** Maintains `RevocationList`, issues Reticulum identity blackhole commands (`blackhole_identity`) when a peer identity hash is known, calls `drop_route`, and rejects outbound `send_single_packet` / `send_lxmf` / `send_ptt_frame` / inbound announce events for revoked hashes.
- **Actor / Device <-> RNS Binding (`bind_actor_device_to_rns`, `verify_actor_device_binding`):** Signs canonical payload (`b"PX-ACTOR-BIND-v1\0" || actor_id || device_token_hash || rns_identity_hash || rns_destination_hash || issued_at_ms`) using the node's Ed25519 identity secret via `PrivateIdentityMaterial::sign` and verifies via `IdentityPublicKeys::verify`.

### RNS-06: Multi-Hop Relay & Heterogeneous Transport (`src/bridge.rs`, `src/node.rs`)
- **Multi-Hop Relay (`enable_transport_relay: true`):** Routes announces, single packets, LXMF opportunistic/direct/resource messages, and PTT traffic across 1–5+ hops (`A <-> B <-> C <-> D <-> E <-> F` and cross-stack Rust <-> Python `rns==1.6.1` / `lxmf==1.3.1`).
- **Custom Bridge Routing Fix (`src/bridge.rs`):** `CustomBridgeInterface` maps `CustomInterfaceKind::WifiAware` to `InterfaceKind::WifiAware` and `BleL2cap`/`Custom` to `InterfaceKind::Pipe` (non-fleet kinds whose `supervisor_kind()` is `None`, ensuring `SendAnnounce` routes independently per interface rather than collapsing into an unattached fleet supervisor), enables `TransportCapability::SameInterfaceRepeat`, and disables Reticulum's 3 Hz / 15s-hold ingress burst throttle + sets `AnnounceBandwidthCap::Unlimited` when `announce_rate_limit_ms` is `None` so 10–100 node tactical bursts converge without multi-second holds.
- **Telemetry & Route Hygiene (`multi_hop_telemetry`, `route_for_destination`, `drop_route`, `purge_expired_routes`):** Exposes hop count, `next_hop_hex`, `via_interface_tag`, `expires_at_epoch_secs`, and enforces `NodeConfig.path_ttl_ms` route pruning.

### RNS-10: Low-Latency RNS Multi-Hop PTT & Floor Control (`src/ptt.rs`, `src/node.rs`)
- **Dedicated PTT Destination:** Registered `PreConfiguredDestination` `("protocolx", &["ptt"])` exposed via `ptt_destination_hash_hex()` and `announce_ptt()`.
- **Compact MsgPack Wire Codec (`PTT_WIRE_MAGIC = b"PXPT1"`):** Encodes voice frames (`send_ptt_frame`) and floor control (`request_ptt_floor`, `release_ptt_floor`), dispatching inbound `RnsInboundEvent::PttFrameReceived` (with multi-hop `hop_count`) and `RnsInboundEvent::PttFloorEvent` via `poll_events()`.
- **Floor Arbitration (`PttFloorArbiter`):** Handles `Grant`, `Busy`, `Preempt` (higher priority), and `Release`.

### RNS-12: Scale & Chaos Readiness (`src/node.rs`, `tests/rns12_scale_chaos.rs`)
- **Shared Tokio Caller Runtime:** `shared_caller_runtime()` uses a process-shared `OnceLock<Runtime>` (`worker_threads(4)`) so 100 concurrent `RnsNode` instances share caller worker threads instead of spawning ~1,000 OS threads.
- **Scale & Chaos Harness (`tests/rns12_scale_chaos.rs`):** Simulates 10, 20, 50, and 100 nodes over hierarchical multi-hop IFAC-isolated `CustomBridgeInterface` (`WifiAware`) clusters with an attached wrong-IFAC rogue node, partition chaos (`hub.set_partition`), and peer revocation (`revoke_peer`).
