# Android PTT 试点

Protocol X Android 客户端和 Web 指挥台共用活动、任务、消息和行动 API。底部对讲栏显示当前对讲组和发言状态。「对讲」和「任务」都可从这里加入频道或按住发言。按住后向服务端申请话权，收到授权后才尝试发布麦克风。松开、失焦或离开前台时结束发言。加入频道后切到其他 App 或锁屏仍可收听，可从系统通知退出频道。断线后用新的收听令牌加入。试点使用合成资料和两个独立的角色访问码。

## 构建 APK

使用 JDK 17、Android SDK Platform 36 和 Gradle Wrapper。首次构建需要访问 Google Maven、Maven Central、Gradle 和 LiveKit Android SDK 使用的 AudioSwitch 模块仓库。

```sh
cd android
./gradlew :app:assembleDebug :app:testDebugUnitTest
```

APK 输出到 `android/app/build/outputs/apk/debug/app-debug.apk`。可用 `adb -s <device-serial> install -r <apk>` 安装到已授权的 Android 设备。

## 单机业务验收

先用模拟器和本机 Ops API 跑任务、汇报、资源变更和现场确认。以下命令在项目根目录运行，使用独立数据库。首次生成后，继续使用 `pilot.env` 内的访问码。

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python deploy/ptt/make_pilot_env.py
set -a
source deploy/ptt/pilot.env
set +a
python run.py --db data/android-rehearsal.db
```

模拟器使用 `http://10.0.2.2:8000` 和 `OPS_PILOT_STAFF_TOKEN`。Web 指挥台使用 `http://127.0.0.1:8000` 和 `OPS_PILOT_DISPATCHER_TOKEN`。

1. 在 Android 选择高尔夫活动，确认接单，再从任务卡进入关联汇报，输入“车辆故障，暂不可用”。
2. 刷新 Web 指挥台，打开这条汇报，生成并确认规则建议。Android 前台同步后显示 03 号备用车和资源调整回执。
3. 在 Android 依次确认机场会合、登车、饭店交接和入住。刷新指挥台核对各节点状态及各自回执。
4. 切换到会议活动，使用相同界面确认负责人和会议节点。切换活动及旋转屏幕时，同一会话内的未发送汇报会保留。

## 本机模拟器

从项目根目录启动 Ops、LiveKit 和受控的信令入口。

```sh
python3 deploy/ptt/make_pilot_env.py
docker compose --env-file deploy/ptt/pilot.env -f deploy/ptt/compose.yaml up --build -d
```

在 Android 模拟器填入 `http://10.0.2.2:8000` 和 `pilot.env` 中对应的调度员或工作人员访问码。桌面指挥台位于 `http://127.0.0.1:8000`。访问码保留在客户端会话内存。容器的示例入口绑定本机。

实体手机通过受信任的 HTTPS Ops 地址和 WSS 信令地址访问试点。在 ECS 或专用联调主机配置证书，并将 `OPS_LIVEKIT_CLIENT_URL` 改为对应 WSS 地址。将 LiveKit ICE 公告地址改为试点设备可达的地址。保持 LiveKit 7880 和 Ops 内部端口私有，HTTPS 代理到 Ops，WSS 代理到本包的信令网关。媒体使用 LiveKit TCP 7881 与 UDP 7882，按实际网络配置放行。

信令网关只接受收听令牌。自托管 LiveKit 可能刷新仍带发布权限的令牌，网关在重新握手时拒绝这类令牌。话权和单路视频发布授权使用单进程管理，试点运行一个 Ops worker。

登录时设置对讲呼号。「对讲」首页显示频道状态、发言者和「最近一句」。「更多」中的「音频输出」显示当前通话设备，点按可选择系统检测到的设备。使用手机侧键调节通话音量。

按住按钮后，App 先申请话权并用暂时静音的音轨建立接收流。提示音和振动后开始发言。松开即停，之后播放结束提示音。通话忙时有单独提示。提示音由本机播放。两台手机用外放联调时拉开距离，也可接耳机交叉测试。

## 现场画面与语音记录

### v0.9 人员绑定与现场操作

- 首次部署用已有试点调度员凭证进入「试点连接」。在「更多 → 人员与频道」新建频道，再添加人员、指定频道并生成绑定码。绑定码有效期 15 分钟。现场人员在蓝黑登录页输入自己的码，核对姓名、呼号和分配的频道后确认。个人凭证在 Android 系统密钥库保护下保存在本机。
- 已绑定人员在对讲首页点频道名切换收听对象。点「成员」选择对方进入一对一按键私呼；同一活动中的私呼使用独立房间及记录。现场画面以所选群组为接收范围。在「频道对话」可逐页加载更早的原音记录。服务端需运行同版转写进程，并把它指向 Ops 的同一个频道登记数据库和语音库。现有 LiveKit WSS 代理继续使用 `/internal/ptt/admission` 验证入组令牌。
- 调度员在「任务 → 发任务」指定一位工作人员、事项、地点和可选的接应人及时间。对方可接单或标记无法响应。工作台区分已派发、终端收到和人为接单。当前已分配的响应任务可从对讲首页打开。任务详情可拍照并确认发送，待发照片由该人员在联网时补传，同一照片编号重试只保存一份。
- 已连接频道的后台收听服务负责轮询派单与私呼提醒。通知需要 Android 通知权限。当前个人绑定支持输入一次性码，视讯通话与 TAK 视频转发由后续阶段验证。

### v0.11 离线处置和通话

- 调度发放的短时绑定码可以显示为二维码。现场端可以用相机拍摄二维码、选取二维码图片，或手动输入码。核对人员后才领取本机绑定。
- 已缓存的派遣任务在断网重启后可以打开。接单、进度确认、无法响应和独立求助按原操作者保存为待同步，恢复连接后用原请求编号重试。服务端拒绝的操作显示「待核对」。同一个任务只有一项待同步的进度操作，避免猜测后续步骤的服务端版本。
- 在任务详情点「请求协助」后，可附现场简述并提交。调度从同一任务确认收到。省略简述时仍可提交。任务照片用系统相机的完整输出，在本机缩放后写入待发队列。
- 在一对一会话点「语音／视讯」。接听方同意后进入专用 LiveKit 房间。结束后释放麦克风和相机。当前是 App 前台通话，来电提醒依赖已运行的收听服务和系统通知权限。

设置 `OPS_VIDEO_ENABLED=true` 后，试点活动的「对讲」页显示「现场画面」。进入后先收看。点击「开相机回传」后开启相机，首次需批准系统相机权限。点「停止回传」「返回对讲」或离开 App 会关闭相机。视频房间与 PTT 房间独立，发布授权只允许一路相机源。

香港试点目前在 LiveKit 内传输和观看现场画面。要在 OpenTAKServer 的「Video Streams」或 ATAK 的「Video」观看同一画面，需要在香港服务端把 LiveKit 的相机轨道转发到 MediaMTX。手机端沿用「开相机回传」入口。参见 [OpenTAKServer 视频文档](https://docs.opentakserver.io/video_streaming.html)和 [LiveKit Egress 输出](https://docs.livekit.io/transport/media/ingress-egress/egress/outputs/)。

香港试点的语音转写运行在独立的 `golf-pilot-transcription` systemd 服务中。使用 `requirements-transcription.txt` 装入独立虚拟环境，预下载多语种 Faster Whisper `base` 模型。`OPS_WHISPER_MODEL_PATH` 指向本地模型目录，`OPS_PTT_VOICE_DB` 指向 Ops 进程和转写进程均可访问的试点 SQLite 文件。单条最多保存 90 秒，最久保存 7 天并保留最近 200 条。模型在 ECS 本地处理，仅为开启该功能的活动保存按键期间的原音。

在「最近一句」可以直接回听原音。「频道对话」显示近期语音和文字汇报，其「全部记录」可查阅更早的内容。「任务」列表可按状态筛选，点开任务依次确认当前步骤，并从「本任务回执」查看接单、资源变更和现场确认。调度员在有候选资源的任务详情中选择车辆或场地。点当前频道或使用「更多」菜单切换活动。

## 双机验收

| 场景 | 可观察结果 |
| --- | --- |
| 双端加入活动频道 | 两个端可接收对方发言 |
| 同时按住 | 只有一个端取得话权，另一端收到频道占用状态 |
| 松手及松手早于授权 | 已开始的发言立即停止，提前松手的设备不会打开麦克风 |
| 发言期间断网 | 连线断开后停止发言，心跳停止后话权在租约到期并成功撤权时释放 |
| 重新入频道 | 客户端取得新的收听令牌，重新按住才发言 |
| 汇报与接单 | 指挥台读到关联任务的汇报与接单回执，服务事实由独立行动确认 |

本阶段使用前台 PTT。锁屏通话、耳机与弱网延迟需要独立测量。现场试点按 [OpenTAKServer 联调验收](../TAK-ECS.md) 核对实际收到的开始和结束事件。
